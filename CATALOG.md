# Каталог: новая техника и барахолка

Две витрины на сайте: `new.html` и `used.html`. Под ними — база SQLite и панель
управления на PHP, обе живут на Бегете.

## Адреса

| Что | Где |
|---|---|
| Витрина новой техники | <https://ivu.ru/new.html> |
| Барахолка | <https://ivu.ru/used.html> |
| Панель управления | <https://ivu.ru/admin/> |
| Пароль | `Ivu-Katalog-2026` — **смените при первом входе** |

Смена пароля — прямо в панели, блок «Пароль». Хранится хешем в
`~/ivu.ru/data/config.php`, вне `public_html`: через браузер этот файл не достать.

## Что умеет панель

- добавить товар: витрина, название, цена, состояние, подпись, описание, Авито;
- загрузить до 6 фото за раз — сжимаются до 1400 px и сохраняются в JPEG;
- у каждого товара галерея: миниатюры под фото, клик меняет главный снимок;
- пометить «продано» одной кнопкой — карточка затемняется, кнопки заказа скрываются;
- изменить любой товар или удалить его вместе с фотографиями;
- поиск по названию и описанию, постраничный список по 20 позиций.

## Где что лежит на хостинге

```
~/ivu.ru/
├── data/
│   ├── catalog.db          ← база (товары и привязка фото)
│   └── config.php          ← хеш пароля
└── public_html/
    ├── catalog-api.php     ← отдаёт товары JSON-ом
    ├── admin/index.php     ← панель
    └── uploads/products/   ← фотографии
```

База и конфиг — **вне** `public_html`, поэтому недоступны по прямой ссылке.

## Как это связано с GitHub

Код (`catalog-api.php`, `admin/index.php`, страницы витрин) лежит в репозитории
и выкладывается автоматически, как остальной сайт.

**Данные и фото — нет.** В воркфлоу выкладки добавлены исключения:

```
--exclude='uploads'
```

Поэтому обновление сайта из репозитория не стирает товары и фотографии.
База вообще вне папки сайта — её выкладка не касается.

## Резервная копия

Товары и фото — единственное на сайте, что не восстанавливается из репозитория.
Раз в месяц стоит сохранять:

```bash
# по SSH
cp ~/ivu.ru/data/catalog.db ~/backup-catalog-$(date +%F).db
tar czf ~/backup-photos-$(date +%F).tar.gz -C ~/ivu.ru/public_html/uploads .
```

Или попросить меня — сделаю выгрузку и положу рядом с проектом.

## Как добавить сотни товаров быстро

Панель рассчитана на десятки записей. Если нужно залить сразу много:

1. пришлите таблицу (Excel или CSV) с колонками: витрина, название, цена,
   состояние, описание, ссылка на Авито;
2. фотографии — папкой, имя файла = название товара;
3. я загружу их скриптом напрямую в базу, минуя ручной ввод.

То же касается массовой правки цен — скриптом быстрее, чем через форму.

## Ограничения, о которых стоит знать

- **Поиск** ищет по названию и описанию, без учёта падежей. Для сотен позиций
  этого хватает; если понадобится «умный» поиск — скажите.
- **Страницы отдельного товара** пока нет: карточки живут на витринах.
  Для поисковиков это значит, что индексируются две страницы витрин, а не
  каждая позиция. Если товаров станет много и нужен приток из поиска —
  сделаем страницу на каждый товар (`/tovar/123`), это отдельная задача.
- **Фильтры** по цене и категориям не сделаны: пока это плоский список
  с поиском. Добавим, когда ассортимент перевалит за сотню.


## Вопросы и комментарии

Под каждой карточкой есть ссылка **«Вопросы»** — открывается окно со списком
опубликованных вопросов и формой «задать свой».

**Как это работает**

1. Посетитель пишет имя и вопрос (телефон — по желанию).
2. Вопрос попадает в базу неподтверждённым — на сайте его пока не видно.
3. В панели `https://ivu.ru/admin/` появляется блок **«Вопросы — ждут проверки»**.
4. Нажимаете **«Опубликовать»** — вопрос появляется на сайте под товаром.
   **«Снять»** — убирает обратно, **«Удалить»** — стирает навсегда.

**Публикация без проверки.** В том же блоке есть галочка — если включить,
вопросы будут появляться сразу. Для публичного сайта это рискованно:
спам и реклама пойдут в открытую. Рекомендую оставить проверку.

**Защита от спама**

- скрытое поле-ловушка: робот заполняет его и получает «успех», но запись не создаётся;
- ограничение: не больше 5 сообщений в час с одного адреса;
- ограничение длины и обязательные поля;
- текст очищается от HTML.

**Где хранится.** Таблица `comments` в той же базе `data/catalog.db`, то есть
вне сайта. Удаление товара не удаляет его вопросы — они остаются в панели
с пометкой «товар удалён», чтобы можно было ответить человеку.

**Ответы.** Сейчас ответить можно только в переписке: телефон или почта,
если посетитель их оставил. Публичные ответы «как в интернет-магазине»
не сделаны — если понадобится, добавлю поле «ответ магазина».

## Вход через Яндекс — только авторизованные

По умолчанию вопросы принимаются от всех, но с модерацией. Если включить
вход через Яндекс ID, писать смогут только вошедшие: спама почти не будет,
а имя подставится из профиля.

**Как включить**

1. Открыть <https://oauth.yandex.ru/client/new> (нужен Яндекс-аккаунт).
2. Название: `Интер-Техника+ — вопросы`. Платформа: **Веб-сервисы**.
3. В поле **Redirect URI** вставить ровно:
   ```
   https://ivu.ru/auth.php?action=callback
   ```
4. В разделе доступов выбрать **«Яндекс ID»** с правами на логин, имя и почту
   (`login:info`, `login:email`).
5. Сохранить. Яндекс покажет **ClientID** и **Client secret**.
6. Открыть `https://ivu.ru/admin/` → блок **«Вход через Яндекс»** → вставить
   оба значения → «Сохранить ключи».

Проверка: на витрине нажмите «Вопросы» — вместо формы появится кнопка
**«Войти через Яндекс»**. После входа форма вернётся, поле имени будет
заполнено и заблокировано.

**Как выключить.** Очистить оба поля в панели и сохранить — вопросы снова
принимаются без входа (с модерацией).

**Где хранятся ключи.** В `data/config.php` рядом с хешем пароля, вне
`public_html`. Секрет никогда не отдаётся в браузер: `auth.php?action=me`
возвращает только «включено/выключено» и имя вошедшего.

**Проверка подлинности.** Перед обменом кода используется параметр `state`,
он сверяется с сохранённым в сессии — так чужой не сможет подставить свой код.
