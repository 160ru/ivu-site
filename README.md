# Пересоздание сайта-визитки ivu.ru

Инструкция «от нуля до опубликованного сайта» для Windows 10/11.
Всё, что описано, проверено на этой машине: сейчас здесь **нет** Node.js, Git
и VS Code — поэтому часть 1 обязательна.

---

## Что уже готово

```
ivu-site/
├─ index.html        ← главная: услуги, партнёры, о компании, контакты
├─ requisites.html   ← реквизиты с кнопками «копировать»
├─ privacy.html      ← политика конфиденциальности (шаблон)
├─ assets/
│  ├─ style.css      ← все стили, токены в :root
│  ├─ app.js         ← мобильное меню, копирование, год в подвале
│  ├─ map.js         ← карта Яндекса, ключ и инициализация
│  ├─ logo.png       ← фирменный знак «ИТ+», прозрачный фон
│  ├─ icon.png       ← иконка сайта и apple-touch-icon, 256×256
│  ├─ og.png         ← превью 1200×630 для мессенджеров
│  ├─ partners/      ← логотипы партнёров (svg)
│  └─ icons/         ← иконки услуг (Lucide, ISC), вставлены inline
├─ tools/og.html     ← из этого файла рендерится og.png, на сайт не идёт
├─ 404.html          ← страница «не найдено»
├─ robots.txt        ← правила для поисковиков
├─ sitemap.xml       ← карта сайта для Яндекса и Google
├─ .htaccess         ← Apache на Beget: HTTPS, редиректы, 404, кэш, gzip
├─ deploy.ps1        ← выкладка на хостинг по SSH (scp)
├─ deploy.cmd        ← обёртка, запускается двойным щелчком
├─ DEPLOY-BEGET.md   ← пошаговая инструкция под ваш хостинг
├─ package.json      ← команды запуска (без зависимостей)
├─ server.mjs        ← локальный сервер на встроенном Node, без npm-пакетов
├─ screenshots/      ← как выглядит: desktop, narrow, requisites
└─ .gitignore
```

Это **статика без сборки**: чтобы увидеть сайт, достаточно открыть `index.html`
двойным щелчком. Никакие зависимости для просмотра не нужны.

**Карта.** В контактах стоит карта Яндекса через JavaScript API 2.1. Ключ лежит
в `assets/map.js` в константе `KEY`. Скрипт API подключается после события
`load`, поэтому первый экран не ждёт карту.

Ключ привязан к домену: в кабинете <https://developer.tech.yandex.ru/services>
в ограничениях ключа должны быть перечислены `ivu.ru`, `www.ivu.ru`
и `160ru.github.io`. Если домен не указан, карта на нём не загрузится.

Что важно по условиям бесплатного использования: сайт открыт всем без
регистрации, логотип и копирайт Яндекса не скрываются, лимит запросов в сутки
не превышается. Рекламные плашки — особенность бесплатного тарифа; снимаются
платным тарифом «Базовый» (2 000 ₽ в месяц за домен). Статичная картинка
(Static API) бесплатно не выдаётся — она стоит от 19 200 ₽ в месяц.

## Часть 1. Что доустановить

Откройте PowerShell и выполните команды по одной. `winget` на машине уже есть.

### 1.1 Node.js LTS — обязательно

Нужен для локального сервера (`npm run dev`), форматирования кода и любых
будущих сборок (Astro, Vite).

```powershell
winget install --id OpenJS.NodeJS.LTS -e --accept-source-agreements --accept-package-agreements
```

Проверка (в **новом** окне терминала):

```powershell
node -v
npm -v
```

Ожидается что-то вида `v22.x.x` и `10.x.x`. Если команды не найдены —
закройте и снова откройте терминал: PATH обновляется только в новых процессах.

### 1.2 Git — обязательно

История версий и автоматический деплой из GitHub. Без Git любая правка —
это «final_v3_новый_точно_последний.html».

```powershell
winget install --id Git.Git -e --accept-package-agreements
```

Проверка: `git --version`

Один раз настройте подпись коммитов:

```powershell
git config --global user.name "Ваше Имя"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
```

### 1.3 VS Code — обязательно

Редактор, в котором вы (или я, с вашего согласия) правите файлы.

```powershell
winget install --id Microsoft.VisualStudioCode -e --accept-package-agreements
```

Расширения (после установки, в новом терминале):

```powershell
code --install-extension ritwickdey.LiveServer
code --install-extension esbenp.prettier-vscode
code --install-extension eamodio.gitlens
code --install-extension usernamehw.errorlens
code --install-extension streetsidesoftware.code-spell-checker
code --install-extension streetsidesoftware.code-spell-checker-russian
```

Что зачем:

| Расширение | Зачем |
|---|---|
| Live Server | Просмотр с авто-обновлением при сохранении |
| Prettier | Единое форматирование HTML/CSS/JS |
| GitLens | Видно, кто и когда изменил строку |
| Error Lens | Ошибки подсвечиваются прямо в строке |
| Spell Checker (+russian) | Опечатки в русских текстах — главный враг визитки |

### 1.4 pnpm — по желанию

Быстрее и экономнее npm. Для статики не обязателен, нужен, если перейдём на Astro.

```powershell
corepack enable
corepack prepare pnpm@latest --activate
```

### 1.5 Аккаунт GitHub — сильно рекомендуется

Бесплатный. Даёт резервную копию кода и деплой «в один `git push`».
Регистрация: <https://github.com/signup>. Если Git-команды в тягость —
поставьте графический клиент:

```powershell
winget install --id GitHub.GitHubDesktop -e --accept-package-agreements
```

### 1.6 Что ещё пригодится, но не обязательно

| Инструмент | Зачем | Как |
|---|---|---|
| Chrome / Edge DevTools | F12 — проверить адаптив, скорость, ошибки | уже есть |
| Figma | Макет до кода, если нужен новый дизайн | <https://figma.com> (браузер) |

## Часть 2. Как посмотреть сайт локально

**Способ 1 — самый быстрый.** Двойной щелчок по `ivu-site/index.html`.
Откроется в браузере, всё работает, кроме переходов по «/privacy.html»
(они рассчитаны на настоящий веб-сервер).

**Способ 2 — локальный сервер (ближе к «боевому»).** Зависимостей нет,
`npm install` не нужен — сервер написан на встроенном модуле Node:

```powershell
cd ivu-site
npm run dev
```

Откройте <http://localhost:3000>. Остановить — `Ctrl+C`.
Порт можно сменить: `$env:PORT=4000; npm run dev`.

Сервер (`server.mjs`) отдаёт файлы с правильными типами, показывает
`404.html` на несуществующих адресах и не пускает за пределы папки сайта.
Именно так будет вести себя и настоящий хостинг.

**Способ 3 — VS Code.** Открыть папку `ivu-site` → правый клик по `index.html`
→ «Open with Live Server».

Проверять обязательно в двух режимах: узкое окно (телефон) и широкое.
DevTools → `Ctrl+Shift+M` — переключение на мобильный вид.

## Часть 3. Как мы работаем над сайтом

1. **Вы присылаете контент** в любом виде: текст в Word, заметки, скриншоты
   старого сайта, фото, логотип, прайс.
2. **Я правлю файлы** — `index.html` под тексты, `style.css` под цвета и шрифты,
   добавляю блоки (отзывы, галерея, цены).
3. **Вы смотрите** и говорите, что поменять. Итерации быстрые: правка вёрстки —
   минуты.
4. **Фиксируем версию** — `git commit`, чтобы всегда можно было откатиться.
5. **Публикуем** на хостинг и переключаем домен.

Важно: пока вы не дали контент, любые тексты на сайте — заглушки.
Сайт-визитка продаёт текстом и контактами, а не анимацией.

## Часть 4. Куда опубликовать

Ваш хостинг — **Beget**, и для статики он подходит без оговорок: SSL
бесплатный, домен и почта в одном месте, поддержка на русском.

Подробная инструкция — [DEPLOY-BEGET.md](DEPLOY-BEGET.md). Коротко:

1. Папка сайта на хостинге: `~/ivu.ru/public_html`.
2. Файлы кладутся в неё: скриптом `deploy.cmd` по SSH, через файловый
   менеджер панели или по FTP (FileZilla).
3. SSL — в панели: «Сайты» → домен → «SSL-сертификаты» → Let's Encrypt.
4. Домен у Бегета настраивается сам; если у другого регистратора —
   меняется только A-запись, MX не трогается.

Состав выкладки — 8 объектов: три страницы, `404.html`, `robots.txt`,
`sitemap.xml`, `.htaccess`, папка `assets`. Скриншоты и служебные файлы
на хостинг не уходят.

> Если понадобится резервный вариант — статику можно бесплатно держать
> на Cloudflare Pages или GitHub Pages, они умеют то же самое. Но для
> домена .ru и почты на нём Beget удобнее: всё в одной панели.

## Часть 5. Домен ivu.ru

Домен уже зарегистрирован у Бегета и делегирован на его NS, A-запись
указывает на сервер хостинга (`m2.spock.beget.com`). **Переключать DNS
не нужно** — сайт откроется сразу после того, как домен прилинкован
к папке в панели.

Проверено 26.11.2026: порт 80 отдаёт заглушку «Домен не прилинкован
к директории», порт 443 закрыт — сертификата нет. То есть сайт сейчас
не работает, и наша выкладка заодно это чинит.

Порядок:

1. Панель → «Сайты» → прилинковать `ivu.ru` к папке `~/ivu.ru/public_html`
   (или добавить сайт, если его нет в списке).
2. Загрузить файлы — раздел 2 в [DEPLOY-BEGET.md](DEPLOY-BEGET.md).
3. Выпустить Let's Encrypt: «Сайты» → домен → «SSL-сертификаты».
4. Проверить редиректы — они уже в `.htaccess`, отдельно настраивать
   не нужно.

Почта домена живёт на Яндекс 360 (`mx.yandex.net`), к сайту отношения
не имеет: MX и A — разные записи, их нельзя путать.

Старую папку сайта не удаляйте 2–4 недели: переименуйте в `public_html_old`,
чтобы вернуться, если что-то забыли.

## Часть 6. Чек-лист перед публикацией

**Содержание**
- [ ] Заменены все заглушки: название, тексты, телефон, почта, адрес
- [ ] Проверены ссылки `tel:`, `mailto:`, мессенджеры
- [ ] Есть логотип и хотя бы одно реальное фото
- [ ] Указаны реквизиты (ИП/ООО, ИНН) — для сайта компании обязательны

**Поиск и соцсети**
- [ ] `<title>` до 60 символов, с городом или специализацией
- [ ] `<meta name="description">` до 160 символов
- [ ] Заполнены `og:title`, `og:description`, картинка `og:image` 1200×630
- [ ] `sitemap.xml` и `robots.txt`
- [ ] Сайт добавлен в Яндекс.Вебмастер и Google Search Console

**Скорость и техника**
- [ ] PageSpeed Insights: 90+ на мобильных
- [ ] Фото сжаты (WebP, до 300 КБ), есть `width`/`height`
- [ ] Страница 404
- [ ] Включено сжатие (gzip/brotli) на хостинге
- [ ] Проверено на телефоне, не только в DevTools

**Юридическое**
- [ ] Политика конфиденциальности (`privacy.html`) — ссылка в подвале
- [ ] Чекбокс согласия на обработку ПД, если есть форма
- [ ] Счётчик Яндекс.Метрики (и упоминание cookie в политике)

## Часть 7. Что мне прислать, чтобы двигаться дальше

1. **Проверка контента**: посмотрите `index.html` — тексты собраны из архива,
   но формулировки стоит подтвердить (года, услуги, «оптом и в розницу»).
2. **Логотип** (SVG или PNG с прозрачным фоном) и **фото** офиса/техники.
3. **Часы работы** и мессенджеры, если нужно добавить к контактам.
4. **Где куплен домен** и **где сейчас хостинг** (доступ к панели DNS).
5. **Формы заявок** — нужны ли: от этого зависит выбор хостинга и бэкенда.
6. **Разделы `/1c/`, `/globus/`, `/nataly/`** — восстанавливать ли их
   отдельными страницами.

## Если позже понадобится больше

- **Astro** — если появится блог, кейсы, много страниц. Статика остаётся статикой,
  но с шаблонами и компонентами: `npm create astro@latest`.
- **WordPress / 1С-Битрикс** — если нужна админка и правки «своими руками» без кода.
  Тяжелее и требует обслуживания.
- **Tilda** — если нужен лендинг за вечер и не важна скорость загрузки.
